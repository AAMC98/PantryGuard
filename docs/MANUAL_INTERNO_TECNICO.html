1. Resumen de Arquitectura y Patrón BFF

Pantry Guard está estructurado bajo el patrón arquitectónico Backend-for-Frontend (BFF). Esta decisión de ingeniería responde directamente a los requerimientos de seguridad para modelos de lenguaje en dispositivos móviles: bajo ninguna circunstancia las llaves criptográficas de APIs comerciales (Google Gemini API) deben residir en el binario del cliente móvil (APK/PWA).

Principio de Aislamiento BFF: El cliente móvil jamás interactúa directamente con los servidores de Google GenAI ni con bases de datos remotas sin intermediación. Toda petición se envía a través de endpoints locales protegidos del servidor Express, el cual actúa como guardián de validación de esquemas, sanitización de datos y limitador de tasa de consumo.

El flujo de datos se resume en la siguiente topología de comunicación:

[ Dispositivo Móvil (Android / iOS) ]
        │  ▲
        │  │  HTTPS con TLS 1.3 (JSON Restringido)
        ▼  │
[ Servidor Express (server.ts) en Render ]
  ├── 1. Middleware de CORS y Headers de Seguridad (HSTS)
  ├── 2. Capa de Rate-Limiting por IP/Usuario (anti-EDoS)
  ├── 3. Memoria Caché de Consultas (MEM_CACHE)
  ├── 4. Motor de Recetas Locales de Emergencia (generateLocalRecipes)
  └── 5. Conector Seguro con Google GenAI SDK (process.env.GEMINI_API_KEY)
              │
              ├── Google Gemini API (Inferencia multimodal estructurada)
              └── Open Food Facts API (Resolución global de códigos EAN/UPC)

5. Especificación de Endpoints y Servicios API

El backend expone rutas REST unificadas bajo el prefijo /api/ai:

1. POST /api/ai/recipes

  • Propósito: Generación de recetas cero desperdicio adaptadas al inventario vigente.
  • Control de Validación: Se usa responseSchema con tipos Type.OBJECT y Type.ARRAY en el SDK de Gemini.
  • Manejo de Errores: Si el LLM devuelve un error de cuota (429) o saturación (503), el catch invoca generateLocalRecipes(), entregando recetas deterministas en menos de 10ms sin interrumpir la experiencia de usuario.

2. POST /api/ai/scan-receipt

  • Propósito: Reconocimiento óptico de caracteres (OCR) y análisis de recibos de supermercado.
  • Payload: Objeto JSON con imageBase64 codificado en Base64 JPEG y tamaño máximo de 2 MB.
  • Salida: Array de artículos detectados con cantidades, categorías y caducidades asignadas según reglas alimentarias.

6. Mecanismos de Visión Computacional y Escaneo 1D

El módulo BarcodeScannerModal.tsx implementa una arquitectura híbrida de escaneo en tiempo real orientada a dispositivos móviles:

  • Hardware Acceleration (window.BarcodeDetector): En navegadores modernos (Android Chrome e iOS 17+), se ejecuta un bucle de inspección a 25 FPS (cada 40ms) conectado directamente a la GPU del dispositivo. Esto permite detectar códigos de barras EAN-13 en menos de 15 ms sin bloquear el hilo principal de JavaScript.
  • Enfoque Continuo por Hardware: Al iniciarse el video, se negocian las capacidades de la cámara con applyConstraints({ advanced: [{ focusMode: 'continuous' }] }) para garantizar nitidez macro a 10–15 cm de distancia.
  • Visor Panorámico Único: Se ocultan los elementos predeterminados de la librería externa con CSS (#qr-shaded-region { display: none !important; }) para mostrar un único marco con relación de aspecto 16:10 y línea láser animada.

8. Marco de Seguridad y Gestión de Credenciales

  • Protección de Secretos: La variable GEMINI_API_KEY reside exclusivamente en el entorno del servidor Node.js y en los secretos encriptados de Render. El archivo .gitignore contiene la directiva .env* para evitar cualquier commit accidental.
  • Prevención de Inyección de Prompts: Toda entrada proveniente de tickets u Open Food Facts se procesa como contenido de datos plano dentro de etiquetas semánticas y nunca se concatena como instrucción de sistema.
  • Salidas Controladas: Cero uso de eval() o inyección de scripts dinámicos en la interfaz de React.

9. Guía de Compilación, Pruebas y Despliegue

Comandos del Proyecto:

ComandoPropósito
npm run devInicia el entorno de desarrollo local con recarga rápida (HMR).
npm run buildCompila los bundles de Vite y empaqueta el servidor con esbuild en dist/server.cjs.
npm startInicia el servidor de producción Express sirviendo los assets estáticos.
npm run lintEjecuta la verificación de tipos de TypeScript sin emitir archivos (tsc --noEmit).

Despliegue Continuo en Render:

  1. Conectar el repositorio AAMC98/PantryGuard en Render.com como Web Service.
  2. Configurar Build Command: npm install && npm run build
  3. Configurar Start Command: npm start
  4. Agregar en Environment Variables: GEMINI_API_KEY con la clave de Google AI Studio.
